# Security headers, applied to every response.
#
# IMPORTANT: this app is meant to run *inside* the Pi Browser, which loads
# Pi ecosystem apps inside its own webview/frame container. X-Frame-Options: DENY
# and frame-ancestors 'none' block that framing outright — the browser refuses
# to render the page at all and shows net::ERR_BLOCKED_BY_RESPONSE before any
# of script.js (including Pi.init/authenticate) ever runs. That's a header
# problem, not an auth problem. X-Frame-Options is dropped entirely here for
# the same reason (older browsers still honor its DENY regardless of any
# frame-ancestors value).
#
# NOTE: There is intentionally NO Content-Security-Policy header here. A
# previous version added one (default-src 'self' + an explicit allowlist of
# script/connect/frame domains), and it caused Pi.authenticate() to reject
# every attempt with a generic "Authentication failed." — almost certainly
# because Pi's real auth flow talks to one or more domains (e.g. under
# pinet.com, or a Pi API host outside *.minepi.com) that weren't in that
# allowlist, and CSP blocks those silently (no readable error, just a failed
# auth). Confirmed by comparing against an earlier known-working deploy,
# which never had a CSP header at all. If a stricter CSP is reintroduced
# later, watch the browser console for CSP violation lines during
# Pi.authenticate()/Pi.createPayment() and allowlist exactly what shows up
# there before assuming it's safe.
/*
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: geolocation=(), camera=(), microphone=(), payment=()
  Strict-Transport-Security: max-age=31536000; includeSubDomains

# Long-term caching for the game's sound effects (including the combined
# sprite file). These never change once shipped (a new sound = a new file
# name), so it's safe to let browsers cache them for a full year instead of
# re-requesting them on every visit — this is what actually cuts down on
# repeat Netlify requests.
/sounds/*.mp3
  Cache-Control: public, max-age=31536000, immutable

# Images rarely change. Cache for a week — long enough to skip re-fetching
# on repeat visits within the same week, short enough that an update still
# reaches users reasonably fast without needing a filename change.
/*.png
  Cache-Control: public, max-age=604800
/*.jpg
  Cache-Control: public, max-age=604800
/favicon.ico
  Cache-Control: public, max-age=604800

# The service worker script itself must NEVER be cached. If it were, browsers
# could keep running an old sw.js that still serves a stale, cached Stockfish
# engine build forever — even after you ship a new CACHE_NAME to force an
# update. no-cache forces a revalidation check on every load (a cheap 304 if
# nothing changed, a fresh copy the moment it does).
/sw.js
  Cache-Control: no-cache

# Code/styles: no cache-busting filenames yet, so keep this short. The
# browser still avoids a full re-download on unchanged reloads via a cheap
# 304 (ETag) instead of a fresh transfer.
/script.js
  Cache-Control: public, max-age=300, must-revalidate
/styles.css
  Cache-Control: public, max-age=300, must-revalidate
/puzzles.json
  Cache-Control: public, max-age=300, must-revalidate
